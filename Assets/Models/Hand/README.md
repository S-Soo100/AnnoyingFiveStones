## 변환 (export_hand.py — Blender CLI로 재실행 가능)

```
/Applications/Blender.app/Contents/MacOS/Blender -b "<원본>.blend" -P export_hand.py
```

1. **리그 조작 위젯 제거** — 원본엔 손 외에 폴리곤 0짜리 컨트롤러가 30여 개 있다
   (Controlador*, Hueso Muneca*, "dedo1,1" …). 그대로 내보내면 빈 오브젝트가 잔뜩 생긴다.
   → `Mano`(메시) + `Huesos Mano`(뼈대)만 남긴다.
2. **손목 절단** — `CUT_X = 2.70` 미만 제거 후 절단면을 holes_fill로 막는다.
   그냥 지우면 구멍이 뚫린 채 보인다. 533 verts 남음.
3. **원점 정렬** — 원본은 손이 X≈4.2에 있어 오브젝트 원점에서 멀다.
   그대로 두면 Unity에서 위치를 잡아도 메시가 옆으로 밀려 화면 밖에 그려진다.
   ⚠️ 메시가 아마추어의 **자식**이라 부모(아마추어)만 옮겨야 한다. 둘 다 옮기면 이동이 두 번 먹는다.

## 삽질 기록 — 다시 하지 말 것

**결론: 손가락은 높은 X, 손목은 낮은 X. 잘라야 할 쪽은 낮은 X다.**

축 방향을 여러 번 틀렸다. 실루엣만 보면 손목과 손가락이 둘 다 "여러 갈래"로 보여 구분이 안 되고,
회전 후 화면 방향을 수식으로 유도한 것도 계속 어긋났다.
**잘라서 렌더해 보는 것만이 확실했다.**

| CUT | 결과 |
|---|---|
| X > 4.50 | 손목 거의 안 줄어듦 |
| X > 4.25 | **손가락이 잘림** (→ 손가락이 높은 X임을 확정) |
| X < 3.86 | 손바닥까지 잘려 손가락만 남음 |
| X < 3.10 | 손바닥 절반이 잘림 |
| X < 2.85 | 손목 제거되나 손바닥이 살짝 모자람 |
| **X < 2.70** | ✅ 확정 — 손바닥 온전, 손목 살짝 노출(허용) |

원본에 긴 팔뚝은 없다. 짧은 손목 그루터기뿐이라 잘라낼 양이 적고(50 verts),
그래서 임계값을 조금만 넘겨도 바로 손바닥을 파고든다.

- 정면 회전 **Euler(0, 90, -90)** — 손바닥이 카메라, 손가락이 위.
  (계산으로 후보를 좁힌 뒤 렌더로 확정. 수식만으로는 결론이 안 났다)

## 뼈대 — 손가락 접기(`HandRig.cs`)

원본 뼈 이름이 전부 `dedo*`(스페인어 '손가락')라 어느 게 어느 손가락인지 이름으로는 알 수 없다.
**손을 가로지르는 좌표 순서로 판별**했다(엄지·검지가 한쪽 끝, 소지가 반대 끝):

| 손가락 | 첫 마디 뼈 | 마디 체인 |
|---|---|---|
| 엄지 | `dedo1.003` | → `dedo2.003` → `dedo3.003` |
| 검지 | `dedo1` | → `dedo2` → `dedo3` |
| 중지 | `dedo1.000` | → `dedo2.000` → `dedo3.000` |
| 약지 | `dedo1.001` | → `dedo2.001` → `dedo3.001` |
| 소지 | `dedo1.002` | → `dedo2.002` → `dedo3.002` |

⚠️ 손가락 사이에 **`Controlador*` 조작 위젯 뼈**가 섞여 있다. 자식을 훑을 때 `dedo` 접두어로 걸러야 한다.

**굽힘 축은 하드코딩하지 않고 뼈대에서 유도한다.**
`손바닥 평면 = (검지관절→소지관절) × (손목→중지관절)` 을 구한 뒤,
각 마디를 `자기 뼈 방향 × 손바닥 법선` 축으로 돌린다. 엄지만 손바닥을 가로지르는 축을 따로 쓴다.

⚠️ **이 모델의 뼈대는 완전 평면이라 손바닥/손등을 뼈 좌표만으로 구분할 수 없다.**
그래서 굽는 쪽은 "화면 앞쪽(카메라 쪽)"으로 잡는다 — 뒤로 말면 손등에 가려 접힘이 안 보인다.
