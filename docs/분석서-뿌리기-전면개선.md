# 분석서 — 뿌리기(Spread) 전면 개선 (초안, GATE 1 산출물)

> 2026-10-28 · CAOF **Critical** · 상태: **사용자 확인 대기** (아래 §7 결정 사항)
> 이 문서는 GATE 2 구현 계획서(game-designer)의 입력이다. 아직 코드는 바꾸지 않았다.

## 1. 요청

1. 낙이 날 때 돌이 더 자연스럽게 **바로 아래로** 떨어지게. 낙 자리에 **그림자가 생기지 않게**.
   1-1. 스테이지마다 보드 밖이 다르다. 10·15살 책상은 보드 밖이 허공이지만, 다른 스테이지는
   보드 옆·뒤에 바닥이 이어져 보인다 → **"화면 아래로 떨어짐" vs "그 바닥에 툭 떨어짐"을 스테이지별로**.
2. 뿌리기 연출이 디자이너·기획자에게 혹평받음 → 다른 게임처럼(닌텐도 스타일이 베스트) 개선.

## 2. 현재 동작 (코드 확인 결과)

| 단계 | 현재 구현 | 위치 |
|---|---|---|
| 준비 | 돌 5개를 손 자식으로 붙여 손바닥 위에 일렬 지터 배치 | `ScatterSystem.BeginScatter` |
| 게이지 | 누르는 동안 0↔1 왕복, 링(LineRenderer) + 좌측 게이지바, 틱 효과음 | `ScatterSystem.Update`, `ScatterRangeIndicator`, `GaugeBarUI` |
| 놓기 | 손 캐스트 0.10s → 커서 복귀 0.15s (윈드업 없음) | `HandController.DoScatterThrow` |
| 비행 | 돌마다 0.05s 간격 출발, **같은 0.5s 포물선**, Y축 스핀 | `DoScatter` 4) |
| 착지 | 목표점에서 정지 → 0.16s 1회 hop + 스쿼시 | `SettleStone` |
| 낙 | **보드 밖 목표점에 일단 착지**(효과음·그림자 포함) → 전부 착지 후 물리 중력 ON, 아래 속도 -4 → 1.0s 후 실패 | `DoScatter` 5) |

### 문제 1의 근본 원인
- **"허공에 착지했다가 떨어진다."** 낙 돌도 보드 밖 목표점까지 포물선을 다 날아가 `h=0`으로 *착지*한다.
  그 자리엔 바닥이 없는데 착지음(`PlayScatterHit`)이 나고 멈췄다가, 그다음 프레임에 물리로 떨어진다.
- **낙 자리 그림자.** `SetState(InAir)`는 `HasBoardMotion`을 지우지 않는다(`Stone.SetState` 410행).
  그래서 `StoneShadow.UpdateFallingShadow`가 계속 마지막 `BoardPos`(보드 밖 허공)에 그림자를 찍는다.
  (정정 2026-10-28, 계획서 C1: 비행 중에는 돌이 InHand라 그림자가 꺼져 있다. 낡은 그림자는 낙 처리의
  `SetState(InAir)` 이후에만 생긴다. 그림자가 "바닥이 있는 곳"을 구분하지 않는다는 결론은 같다.)
- **스테이지 무관.** 보드 밖이 무엇인지에 대한 데이터가 없다. `BoardProfile`은 사다리꼴 4값뿐이다.

### 문제 2 — 연출이 밋밋한 이유 (추정, 디자이너 피드백 원문 미확인)
- **예비동작이 없다.** 게이지 동안 손·돌이 가만히 있다. 힘을 모으는 느낌이 링 크기에만 있다.
- **모든 돌이 같은 궤적.** 체공 0.5s 고정, 높이 1.2~1.8, 출발 간격 0.05s 균일 → 기계적으로 보인다.
- **착지가 "멈춤"이다.** 한 번 살짝 튀고 끝. 구르거나 미끄러지지 않고, 먼지·충격 표현이 없다.
- **소리가 단조롭다.** 5종 클릭음 + 피치 0.9~1.1. 돌 순서와 무관.
- **링이 디버그 선처럼 보인다.** 얇은 LineRenderer 원.
- 스핀이 Y축 회전이라 정면 카메라에서 거의 안 보인다.

## 3. 스테이지별 "보드 밖" 판독 (아트 실측 — **사용자 확인 필요**)

배경+보드 레이어 합성 이미지로 판독했다. 변(앞/뒤/좌/우)마다 아래 셋 중 하나로 본다.

- **낭떠러지(Ledge)** — 보드 밖이 허공. 돌이 가장자리를 넘는 순간부터 **화면 아래로 떨어진다**. 그림자 없음.
- **같은 높이 바닥(Flat)** — 보드 밖에 같은 높이 면이 이어짐(책상 위 패드 바깥 등). 돌이 **그 바닥에 툭** 떨어져 튀고 미끄러진다. 그림자는 그 바닥에 생긴다. 판정은 여전히 낙.
- **낮은 바닥(Step)** — 보드 밖이 조금 아래(침대 매트리스 등). 짧게 떨어져서 **툭** 멈춘다. 그림자 없음.

| 스테이지 | 장면 | 앞 | 뒤 | 좌·우 |
|---|---|---|---|---|
| 10·15 | 교실 책상 | Ledge | Ledge(책상 뒤로 가려짐) | Ledge |
| 20 | 포장마차 테이블 | Ledge | Ledge(가려짐) | **Flat**(옆 테이블) |
| 25·30 | 사무용 책상 위 패드 | Ledge | **Flat**(책상) | **Flat**(책상) |
| 35 | 육교 계단 길 | Ledge | **Flat**(길이 이어짐) | Ledge(난간 너머 잔디) |
| 40·45 | 나무 책상(화면 전폭) | Ledge | **Flat** | **Flat** |
| 50·55 | 침대 위 놀이판 | Ledge | Ledge | Ledge (**사용자 확정**: 10·15살처럼 바로 아래로) |

> 사용자 확정(2026-10-28): 50·55살은 전 변 Ledge, 나머지 스테이지는 위 표대로.
> 결과적으로 Step(낮은 바닥)을 쓰는 스테이지가 없다 → Step 종류는 **만들지 않는다**(Ledge/Flat 2종).

> 뒤로 떨어지는 Ledge는 실제로는 책상에 가려져야 한다. 돌이 보드 뒷변을 넘으면 짧게 내려가며
> 빠르게 투명해지게 처리한다(가려짐 흉내). 앞·좌우 Ledge는 화면 하단 밖까지 떨어진다.

## 4. 설계 방향

### 4-A. 낙 낙하 (문제 1) — 추천안
1. **목표점까지 날아가지 않는다.** 비행 중 돌의 바닥 지점이 보드 경계를 넘는 순간을 계산한다(보드 좌표라 직사각형 교차 한 번).
2. 경계를 넘은 뒤 그 변의 종류대로 처리한다.
   - **Ledge:** 수평 속도는 그대로 두고, 높이를 0 아래로 계속 내린다(중력 가속). `BoardSpace.ToScreen(pos, h<0)`이
     화면 아래로 내려간 위치를 주므로, 물리 없이 코루틴만으로 "가장자리에서 아래로 떨어지는" 궤적이 된다.
     화면 밖으로 나가면 끝. 뒷변은 투명해지며 사라진다.
   - **Flat:** 보드 밖 바닥에 그대로 착지 → 아래 4-B의 착지 연출(튐·미끄러짐)을 그대로 쓴다. 착지음은 둔한 톤.
   - **Step:** Ledge처럼 떨어지다 `h = -깊이`에서 착지, 한 번 짧게 튀고 정지.
3. **그림자 = 바닥이 있는 곳에만.** 그림자의 지면 지점이 보드 안이거나 Flat 영역일 때만 보인다.
   Ledge/Step 너머로 나가는 순간 짧게(0.08s) 사라진다. `InAir`인데 보드 밖에 남는 낡은 그림자도 없앤다.
4. 낙 돌에는 착지음을 내지 않는다. 대신 가장자리를 넘을 때 짧은 "휙" + 화면 밖 도달 시 멀리서 나는 "딱"(또는 무음).
5. 실패 전환 타이밍: 마지막 낙 돌이 사라지거나 정지한 뒤 0.3s (현재 고정 1.0s).

**데이터:** `StageConfig`에 변 4개 프로필을 추가한다(예: `BoardEdges { Front, Back, Left, Right }`, 각 변 = 종류 + Step 깊이).
판정(낙 여부)은 **바뀌지 않는다** — 그대로 `BoardSpace.ContainsWithMargin`. 바뀌는 것은 낙이 *어떻게 보이는가*뿐이다.

### 4-B. 뿌리기 연출 (문제 2) — "닌텐도식 손맛" 패키지

원칙(리서치): 예비동작 → 짧은 정지(히트스톱) → 과장된 탄성(스쿼시·스트레치, 오버슈트) → 먼지·소리로 착지 확인.
과하지 않게, 상황에 맞을 때만. **물리 임펄스는 쓰지 않는다**(donts/game.md #20) — 전부 보드 좌표 코루틴.

| 순간 | 지금 | 개선안 |
|---|---|---|
| 꾹 누름 | 손 정지 | 손이 주먹을 쥐고(돌이 손 안으로 모임) 게이지에 비례해 **달그락 흔들림**. 흔들림 세기·딸깍 소리가 게이지 따라 커짐 |
| 링 | 얇은 선 | 보드에 눌러 붙은 **반투명 원판 + 점선 테두리**, 게이지 따라 천천히 숨쉬듯 맥동. 색 규칙(U자 위험색)은 유지 |
| 놓음 | 즉시 날아감 | **0.05s 정지**(손·돌만, `Time.timeScale` 안 건드림) → 손이 확 펼쳐지며 스쿼시 → 돌이 부채꼴로 터져 나감 |
| 비행 | 균일 포물선 | 출발 간격 랜덤(0.02~0.07s), 체공·높이 돌마다 다르게. 상승 중 진행 방향으로 살짝 **스트레치** |
| 착지 | 1회 hop | **목표점 앞에서 먼저 닿고** → 25% 높이로 한 번, 8%로 한 번 튀며 목표점에 도달 → 짧게 미끄러져 정지. 닿을 때마다 스쿼시 + **흰 먼지 퐁**(코드로 그린 동그라미 4~6개) |
| 소리 | 5종 클릭 | 착지 순서대로 **음이 한 칸씩 올라가는** 딸깍(도-레-미…). 튈 때마다 작게 반복 |
| 마무리 | 없음 | 모든 돌이 안전하게 멈추면 짧은 "짠" 효과음 1회 (낙이면 생략) |

안전장치: 튀는 착지는 **목표점 안쪽에서 시작해 목표점에서 끝난다**. 최종 위치는 지금과 똑같은 `boardTargets[i]`라서
배치·낙 판정·줍기 간격 밸런스는 바뀌지 않는다(donts #19 SOT 유지).

## 7. 가정 / 선택지 / 실패 시나리오 / 검증 / 결정 사항

**가정**
- 확인: 낙 판정 로직은 그대로 두고 표현만 바꾼다(밸런스 불변) · `ToScreen(pos, h<0)`이 화면 아래 위치를 준다(투영식 확인 필요, GATE 2에서 테스트).
- 미확인: 디자이너 혹평의 **구체 지점** · 50·55살 좌우 변의 의도 · 새 효과음 소스 확보 여부.

**선택지**
- 낙: (A) 경계 교차 후 변 종류별 연출 — **추천** / (B) 현행 유지 + 그림자만 끄기(문제 1-1 미해결) / (C) 물리 낙하(금지 규칙 #20 위반).
- 연출: (1) 위 손맛 패키지 전부 — **추천** / (2) 착지(튐·먼지·음계)만 먼저 / (3) 레퍼런스 영상을 받아 그에 맞춰 재설계.

**실패 시나리오**
- 15살(돌 18개): 출발 간격 × 18 → 뿌리기가 길어짐, 음계가 너무 높이 올라감 → 돌 수에 따라 간격 압축, 음계는 한 옥타브에서 순환.
- 튀는 착지가 경계 근처 돌을 시각적으로 밖에 찍음 → 튐은 목표점 안쪽에서만, 경계 0.5 이내 돌은 튐 축소(현 hop 규칙 계승).
- 히트스톱을 `Time.timeScale`로 하면 Flee/Obstacle 기믹·게이지가 같이 멈춤 → 손·돌 코루틴만 멈춘다.
- 착지 시간이 길어져 `OnScatterComplete`(Flee 등) 시작이 늦어짐 → 마지막 정지 시점에 호출, 총 길이 상한 1.2s.
- 뒤 Ledge 페이드가 Monochrome/Spotlight 기믹의 알파 조작과 충돌 → 기믹별 알파 경로 확인 필요.

**검증 방법**
- 에디터: `DebugScatterNow(g)`로 10개 스테이지 × 게이지(0.1/0.45/0.95) 실행, MCP 화면 캡처로 낙 경로·그림자 확인.
- 로그: 낙 돌별 "교차 변/종류", 최종 위치가 기존 목표와 동일한지(차이 0) 출력.
- **사용자만 확인 가능:** 손맛 체감, 디자이너 재평가.

## 8. 사용자 결정 (2026-10-28 확정)
1. **혹평 원문:** 구두 피드백, 문서 없음. 요지는 **"싸구려 같다"**.
   → 해석: 속도·타이밍이 아니라 **완성도·무게감·일관성** 문제. 얇은 디버그 선 링, 전부 같은 궤적,
   튐 없이 멈추는 착지, 단조로운 클릭음이 "임시 구현"처럼 보인다. 개선 기준은 "과하게 튀는 장난감"이 아니라
   **깔끔하고 무게 있는 손맛**(돌은 가볍게 통통 튀는 고무공이 아니라 단단한 돌). 효과는 적게, 대신 정확하게.
2. **§3 판독:** 50·55살은 10·15살처럼 전 변 Ledge. 나머지는 표대로 확정.
3. **범위:** **전부.** 뿌리기 낙 + 플레이 중 낙(튕겨 나간 돌·받기 실패·유예 밴드 너머 등 모든 낙 경로)에
   같은 낙하·그림자 규칙을 적용한다.
4. **연출:** 선택지 (1) 손맛 패키지 전부.
