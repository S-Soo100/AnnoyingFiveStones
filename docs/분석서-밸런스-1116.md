| 항목 | 실측값 (출처) | 체감 |
|---|---|---|
| 체공 | 올라가기 **1.0s** + 내려오기 **1.5s** (`GameScene.unity` 1044~1045) × 단별 배율 1.0/1.15/1.25/1.35 (`HandController.cs:25`) → **1단 2.5s ~ 4단 3.4s** | 실제 공기는 0.5~0.8s. 3~5배 길다 |
| 줍기 | 누른 순간부터 **2초 쓸어담기** (`HandController.cs:62`) | 한 번 누르면 체공의 60~80%를 커버 |
| 받기 | 돌이 **던진 자리 그대로 수직 낙하**, 그림자가 조준선 (`HandController.cs:627~637`) | "그림자로 손 돌려놓기"만 하면 된다 |
| 받기 판정 | 손 반경 1.6 / 손바닥 0.8 (보드 단위, `HandController.cs:823`) + 지면 도달 시 최후 판정 (`:784`) | 관대 |
| 실패 대가 | **그 나이의 1단**으로만 회귀 (`GameSession.OnFail`) | 잃는 게 최대 5단 분량 |
| 클리어 연출 | 1단 클리어와 **나이 클리어(5단 꺾기)가 똑같은** "CLEAR!" 1.5s + 같은 징글 (`GameManager.DoClearTransition` / `DoClearThenMent`) | 큰 성취와 작은 성취가 구분 안 됨 |
| 받기 성공 | SFX 1개(`CatchSystem.cs:216`) | 손맛 없음 |

**핵심 발견 — 11-15에 보정이 두 번 겹쳤다.**
11-15 "누르는 순간 집기"로 줍기가 빡빡해져 **단별 체공 배율**(최대 1.35×)을 넣었고,
같은 날 2차로 **2초 쓸어담기**를 다시 넣어 줍기를 풀었다. 그런데 배율은 그대로 남았다
(기획서 §4 "단별 체공 배율은 유지(사용자 결정)"). → 줍기 난이도를 푼 보정이 2중으로 걸려 있다.

## 1. 요청 1 — 1~4단 낙하 속도 랜덤 (현재 ~ 30% 빠르게)

### 해석
"속도 30% 빠르게" = 낙하 시간 ÷ 1.3 → **낙하 시간 × [0.769, 1.0] 균등 랜덤, 던질 때마다 새로 뽑음.**
(대안 해석: 낙하 시간 −30% = ×0.7 → 속도로는 43% 빠름. 아래 수치는 첫 해석 기준)

### 효과 실측 계산
| 단 | 현재 체공 | 가장 빠를 때 | 평균 감소 |
|---|---|---|---|
| 1단 | 2.50s | 2.15s (−14%) | −7% |
| 4단 | 3.38s | 2.90s (−14%) | −7% |

⚠️ **정직한 평가: 이것만으론 "노잼"이 안 풀릴 가능성이 크다.** 올라가기는 그대로라 총 체공이 평균 7%만 줄고,
2초 쓸기 + 1.35× 배율이 그대로면 여전히 여유롭다. 다만 "매번 다르다"는 **긴장감**(돌이 정점에서 툭 빨라지는 순간)은 확실히 생긴다.
→ **1번은 하되, 2번의 체공 노브와 같이 가는 것**을 추천.

### 구현안 (1파일, 약 5줄)
- `HandController.cs:698` `effectiveDownDuration`에 `Random.Range(1f/1.3f, 1f)`를 곱한다. 던지기마다 1회 추첨, 로그에 배율 출력.
- 범위는 상수 1개(`FallSpeedRandomMax = 1.3f`)로 둔다 — 플레이로 조정.
- 5단(`HandController.Stage5.cs`)은 건드리지 않는다.

### 기믹과의 겹침 (확인 필요)
| 나이 | 영향 | 판단 |
|---|---|---|
| 40살 중력 | 무게별 배율 위에 곱해짐. 검정 0.38~0.5 / 회색 0.77~1.0 / 흰 1.38~1.8 → **구간이 안 겹쳐 무게 구분 유지** | 적용 OK |
| 55살 모노톤 | 낙하 2.2s → 최소 1.69s. 1단 기억 1.6s 이후 줍기 창 1.6s → **1.09s**로 좁아짐 | 적용하되 플레이 확인 / 또는 제외 |
| 그 외 | 영향 없음 | 적용 |

### 유저 체험 시뮬레이션
```
[화면] 돌을 던진다 → 1초간 떠오른다 (매번 같음)
[조작] 올라가는 동안 꾹 눌러 바닥 돌을 쓸어담는다
[반응] 정점에서 돌이 떨어지기 시작 — 이번 판은 평소보다 확 빠르다
[조작] 줍던 걸 멈추고 손을 그림자 위 하늘로 급히 올린다
[감정] "어 빨라!" — 조급함. 느린 판엔 "휴" 하는 여유
[위험] 빠른 판에 4개 줍기 중이면 덜 주워 실패 → "운빨"로 느껴질 수 있음.
       단, 속도는 정점부터 눈에 보이므로 '몰라서 죽는' 건 아님 (§8 원칙 충족)
```

## 3. 가정

- (확인) 체공·쓸기·받기 수치는 위 파일:줄에서 직접 읽음.
- (확인) 낙하 오버라이드는 중력·모노톤 2곳만 사용 (`SetThrowDownDurationOverride` grep).
- (확인) `GameManager.HangTime`(baseHangTime 5)은 참조처가 없는 잔존 코드 — 체공과 무관.
- (미확인) "노잼"의 주원인이 체공인지 받기인지 — 사용자 플레이 체감만 확인 가능. 그래서 숫자 노브부터 추천.

## 4. 실패 시나리오

- 낙하가 빠른 판에 4단(4개 줍기)이 겹치면 "운으로 죽었다" 느낌 → 범위를 1.2로 낮추거나 4단만 상한 완화.
- A1+A2+1번을 한 번에 넣으면 과하게 어려워질 수 있음 → 한 번에 1~2개씩 넣고 플레이.
- 씬 직렬화값이 코드 기본값보다 우선 → A2는 반드시 씬 값까지 같이 바꿔야 반영됨.
- Play 중 재컴파일은 Play 재시작 전까지 반영 안 됨(donts #21).

## 5. 검증 방법

- 콘솔 `[Hand] Airtime stage=N xM: up=… down=…` 로그에 랜덤 배율이 던질 때마다 다르게 찍히는지 (MCP `get_console_logs`).
- 40살(무게 구분)·55살(기억 후 줍기 창) 1판씩 — GameTestMenu 나이 이동.
- 재미 판단은 **사용자만 확인 가능**.

## 6. 사용자가 정할 것

1. "30% 빠르게" 해석 — 속도 1.3배(시간 ×0.77, 추천) vs 시간 −30%

3. 1번과 같이 넣을 난이도 노브 (A1/A2/A3/A4)
