## 1. 가정 (확인/미확인)

- ✅ 확인: 모든 레이어가 1600×900 풀프레임 → offset=0 / scale=1로 포개면 원본 합성과 동일. 정렬 측정 대부분 불필요.
- ✅ 확인: 영역 가이드 7장 픽셀 실측 — BoardSpace 공통 보드(뒷변 px≈566 y, [399,1201] / 앞변 px≈797 y, [286,1314])와 비교:
  - 앞변: 전 스테이지에서 가이드가 더 넓음 → 돗자리 앞변은 테이블 안에 안착.
  - 뒷변: 가이드가 소폭 좁음 — 10세 약 12px(월드 0.19), 20세 약 35px(월드 0.54) 돗자리 뒷변 모서리가 테이블 밖으로 삐짐. → §3 정렬 방침.
  - 40/45세 가이드는 상단 y≈526부터 전폭(테이블이 화면 전폭) → 정렬 문제 없음.
- ✅ 확인: v17 보드 통일 이후 스테이지별 BoardQuad는 미사용(`BoardSpace.UnifiedQuad` 고정). **낙 판정은 이번 변경과 무관** — 배경은 순수 시각.
- ✅ 확인: v18에서 bgImageQuad는 알파 지원(Transparent) → 불투명/투명 bg 모두 안전.
- ⚠️ 미확인(구현 시 실측): Cloth 돗자리·돌의 월드 z → board quad의 z 끼움 위치(배경 뒤 ← board ← 돗자리 ← 돌).

## 2. 적용 방식 — 선택지와 추천

**A안 (추천): bg + board 2레이어 풀스크린 quad.**
- bg → 기존 `BackgroundImage` 경로 교체만.
- board → StageConfig에 새 필드 `BoardImage` 추가, BackgroundManager가 **풀스크린 quad를 하나 더**(bgImageQuad와 동일 transform 로직 재사용, z만 돗자리·돌 뒤) 띄움.
- 근거: 레이어가 분리돼 있어야 ①배경은 고정한 채 테이블만 미세 정렬 가능 ②돌 그림자·돗자리가 테이블 위, 배경 앞이라는 깊이 표현이 성립.
- 기존 MatImage 경로(MatCenter/MatSize 부분 quad)는 재사용하지 **않음** — 그건 "이미지 일부를 오려 특정 월드 영역에 붙이는" 방식이라 풀프레임 레이어엔 과잉. v17의 "MatImage 비활성" 결정도 그대로 유지.

**B안: 외부에서 bg+board를 합성해 1장으로.** 코드 변경 최소(경로 교체뿐)지만, 테이블만 조정 불가 + 35세처럼 레이어 없는 스테이지와 비대칭 해소 안 됨. 기각.

**C안: board를 돗자리 대체로.** 기획서 v11 §2 "배경은 분위기, 보드(돗자리)는 별도 오브젝트" 위반 + v17 "노는 자리 하나" 회귀 유발. 기각.

## 3. 돗자리 뒷변 삐짐 정렬 방침

20세 등에서 돗자리 뒷변이 테이블보다 월드 ~0.5 넓음. 보정 선택지:

1. **수용 (1차 적용값, 추천)** — v17 노트대로 돗자리는 "위에 놓인 물건"이라 테이블과 변이 나란할 필요 없음. 뒷변 모서리 2점이 살짝 걸치는 정도는 플레이 중 돌·손에 가려짐.
2. 스테이지별 `BgImageScale`을 1.03~1.05로 키워 테이블을 넓힘 — 배경 가장자리 크롭 발생, 라이브튜닝으로 확정값 잡기.
3. 디자이너에게 테이블 뒷변 확장 요청 (아트 수정).

→ 1로 적용 후 10단 순회 스크린샷을 보고 거슬리는 스테이지만 2·3 검토.
