## 5. 발견·메모 (버그 아님)

1. **mcp-unity 1.5.0 토큰 인증**: 업그레이드 후 구 브리지 프로세스가 hang → 프로세스 재시작으로 해결. 재발 시: `ps -ax | grep mcp-unity` 후 오래된 node kill.
2. **합성 입력 한계 실측**: 줍기 판정은 보드좌표 원(0.346u)이라 화면상 세로 ±4px — 자동화 클릭으로는 줍기 성공 재현이 매우 어려움(사람에겐 쓸기 조작으로 자연스러움). 받기는 "던진 돌 x에 미리 가 있기"로 성공 재현됨.
3. **던지기 와인드업 ~1.65초** 동안 phase=Throw라 줍기 입력 무시 — 설계 의도 범위로 보이나, 빠른 유저가 "줍기가 씹힌다"고 느낄 수 있는 구간(참고용).
4. 이번 세션에서 추가된 unity CLI(`com.unity.pipeline`) `script eval`이 플레이 중 상태 조회에 매우 유효 — 향후 플레이 검증 표준 도구로 권장.

## 6. 다음 세션 사람 테스트 항목 (v25~v30 반영, 2026-10-28 갱신)

> v23(돗자리 디버그화)·v25(유예 밴드)·v26/v29(스테이지별 보드)·v27/v30(그림자)·v29(돌 +15%)·v30(밴드 균일화)이 전부 코드 검증만 통과한 상태. 아래는 **사람 플레이로만 확인 가능한 체감 항목**.

1. **유예 밴드 체감** (v25 설계 → v30에서 전 방향 0.8 균일화): 돌이 보드 경계 살짝 밖(≤0.8유닛)에 떨어져도 낙이 아니고 줍기 가능해야 함. 특히 **앞변 바로 밖**(v30 전엔 사실상 즉시 낙이던 구간)과 사선 측변에서 "아트 테이블 위인데 낙" 억울함이 사라졌는지. 폭 조절 노브: `BoardSpace.GraceBandWidth`(0.8). 너무 너그러우면 낮추고, 여전히 억울하면 올림 — 뿌리기 낙 확률 밸런스와 같이 논의.
2. **착지 그림자 연속화** (v30): 높은 던지기·뿌리기에서 낙하 그림자 → 착지(접지) 그림자로 전환되는 프레임에 크기/모양 점프가 없는지. 접지 그림자 자체(v27 납작 타원)의 어색함 재발 여부도 같이.
3. **돌 기본 크기 +15%** (v29, 0.3→0.345): 보드 앞뒤 돌 크기 차이(사다리꼴 비율 ~0.54)가 여전히 거슬리는지. 거슬리면 돌 크기 추가 조정이 1차 노브(보드 비율은 아트 정합에 잠김).
4. **스테이지별 보드 정합** (v26·v29): 10단 순회하며 Tools → "디버그: 보드 영역 오버레이 토글"로 빨간 오버레이를 켜고 아트 테이블과 일치 확인. 7·8단(40·45세)은 아트가 화면 전폭이라 제안값 — 체감 우선 확인 대상.
5. **기존 시트(10-17) 잔여**: A2·A4~A6, B2~B4·B6, C1~C3·C5(디자이너), D3~D4, E 전체(쫀득 체감), G 전체 — 특히 **G1 줍기 포함 풀사이클 1회**(합성 입력으로 미시연, §5-2).
6. **기획 미결 이월**: 뿌리기 낙 확률 밸런스(밴드 폭 노브 포함) / 디자이너 아트 요청 후보(15세 전용 배경, 35세 판 레이어).
