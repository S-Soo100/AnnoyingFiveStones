## 0. 왜 v17 "보드 통일"을 뒤집어도 되는가 (정직한 리스크 평가)

v17이 스테이지별 quad를 없앤 이유는 **"배경마다 손으로 재서 맞추던" 수작업 측정이 버그의 뿌리**였기 때문(v11·12·14·16). 지금은 조건이 다르다:
- 디자이너가 스테이지별 **영역 가이드 PNG**를 정식 제공 → 수치가 아트의 SOT에서 **스크립트로 일괄 산출**된다(눈대중 아님. 에지 직선 피팅, 재현 가능).
- 판정·시각·배치가 전부 `BoardSpace.Current` 하나를 읽는 구조(v17의 진짜 유산)는 **그대로 유지** — 바뀌는 건 "그 하나의 값이 스테이지별로 로드된다"는 것뿐. 보드 정의가 여러 곳에 흩어지는 옛 구조로 돌아가는 게 아니다.
- 되돌리기: 프로필 테이블을 v22 단일값으로 바꾸면 끝.

## 4. 구현 설계 (파일/함수)

| 파일 | 변경 |
|------|------|
| `BoardSpace.cs` | 4상수(Back/FrontScreenY·Back/FrontHalfWidth)+CenterScreenX → **static 프로퍼티** + `ApplyProfile(BoardProfile)`로 geometry 재생성. 기본값 = 1단 프로필. `GraceBandWidth`·논리 16×9는 const 유지 |
| `StageConfig.cs` | `BoardProfile` struct(back/front y·half, centerX) 필드 + 10단 값(§3). 구 `BoardQuad`(v17 이후 미사용 레거시) 주석 명확화 |
| `BackgroundManager.cs` | `ApplyStage` 첫머리에 `BoardSpace.ApplyProfile(config)` → 이후 기존 흐름(UnifiedQuad 등록→SkyFloorY 자동→CatchSystem 재계산)이 그대로 스테이지값을 탄다 |
| `BoardMatVisual.cs` | 디버그 오버레이 텍스처 비율이 스테이지별로 달라짐 → 표시 중일 때만 재생성(숨김 시 비용 0) |

소비자 28곳 전수 grep 완료 — 전부 런타임 참조라 **수정 불필요**(컴파일타임 상수 요구는 GraceBandWidth뿐, 유지됨). SkyFloorY·CatchFailY·손 원근·산개 반경·유예 밴드 모두 `Current` 경유라 자동 추종.

## 5. 가정 (확인/미확인)

- ✅ 소비자 전수 런타임 참조 (grep 28곳).
- ✅ SkyFloorY는 quad 등록 시 자동 동기(v11-fix3) — 스테이지 전환마다 갱신됨.
- ✅ 테스트는 자체 픽스처 geometry — BoardSpace 동적화와 무관.
- ⚠️ 미확인: 스테이지 "전환 중"(돌 비행·전환 연출)에 프로필이 바뀌는 타이밍 race — ApplyStage는 스테이지 시작 시점 1회라 기존 BoardQuad override와 동일 타이밍. 구현 후 전환 반복으로 확인.
