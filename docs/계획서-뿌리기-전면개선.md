## 3. 가정

**확인됨**
- A1. `Project`는 높이를 화면 y에 선형으로 더하고 x는 바꾸지 않는다(BoardGeometry.cs:99). 그래서 h<0이면 화면에서 아래로 내려간다.
- A2. `PerspectiveScale`은 h를 0 이상으로 자른다(:125). v>1이면 앞변 크기로 고정된다(:130). v<0이면 계속 작아지다가 v<-1.18에서 음수가 된다. 그래서 뒷변 낙하에서는 보드 y를 v ≥ -0.8로 클램프한다.
- A3. 판 레이어는 z=30, 배경은 z=40이다(BackgroundManager.cs:300, 304). 둘 다 투명 큐로 그려진다(:329-338). 돌은 z=0이다(Stone.cs:235).
- A4. 앞변이 아닌 Ledge 변이 있는 스테이지는 10·15·20(뒤)·35(좌우)·50·55다. 이 중 판 레이어가 없는 곳은 **35살 하나**다(StageConfig.cs:176). T4 폴백이 실제로 쓰이는 곳은 35살 좌·우 변이다.
- A5. 판정 위치는 다음과 같다.
  - 뿌리기: `ContainsWithMargin(target, 0.2)` (ScatterSystem.cs:366)
  - 회수 루프: 같은 식 (:351)
  - 플레이 중: `IsOutsideMat(p, 0.8)` (GameManager.cs:305, 393)
  - 튕김: `y ≤ FrontScreenY` (CatchSystem.cs:36, 71)

  D9 이전의 Flat 변 동작과 튕김 판정은 **그대로** 둔다.
- A6. 뿌리기 중에는 GameManager의 장외 감시가 꺼져 있다(GameManager.cs:266-269, 286).
- A7. `OnScatterComplete` 소비자인 Obstacle은 SetBoardMotion으로 돌을 옮긴다(ObstacleGimmick.cs:289). Sequence는 위치로 색을 배정한다(SequenceGimmick.cs:38). ColorSelect는 기존 돌 위치와의 거리를 잰다(ColorSelectGimmick.cs:116-128). 그래서 완료 신호는 **모든 착지가 끝난 뒤**에만 보낸다.
- A8. OnFailed는 즉시 ResetAllStones를 부른다(GameManager.cs:654). ResetAllStones는 돌의 **위치를 바꾸지 않는다**(:706-723). 실패 순간에 공중에 있던 돌은 실패 화면 동안 그대로 떠 있다. 그래서 실패 직전에 미완료 토스를 최종 자세로 맞춘다.
- A9. EditMode 테스트 러너가 있다(`Assets/Tests/EditMode/`).
- A10. 뿌리기 출발점 S는 보드 사각형 안으로 클램프된다(ScatterSystem.cs:392). 안착 목표 F는 D9 기준 안전 영역 안이다. 사각형은 볼록하므로 선분 S→F 위의 모든 점도 안전 영역 안이다. 이 덕분에 첫 접촉점 A(S와 F 사이)도 항상 안이다(검수 🟡 전제 명시).

**미확인**
- U1. URP에서 z=35 가림이 의도대로 보이는지 → M1-S7 스크린샷으로 확인. 실패하면 h<0 순간 렌더러를 끈다.
- U2. 손가락 0.55가 쥔 손으로 보이는지 → 사용자가 눈으로 확인.
- U3. 착지음 기준 클립(기본 scatter_hit_2), A/B 음계, 마무리음 → 사용자 청취.
- U4. 20살 판 레이어에는 테이블 위로 불투명 도시 띠가 함께 그려져 있다(age20_board.png 직접 확인). 뒷변 낙에서 1~2프레임 일찍 숨는 게 눈에 띄는지 확인.
- U5. 공유 pitch 간섭(C5)은 Unity의 일반 동작에 근거했다. 에디터에서 재현해 확인한다.
- U6. D9 이후 Ledge 스테이지에서 물리 표류로 인한 플레이 중 낙 빈도(F15) → M2 플레이로 측정.

### 5-2. D9 — Ledge 판정선 = 보이는 가장자리 (의도된 판정 변경)

**무엇이 바뀌나**
- 뿌리기 안전 영역: `ContainsWithMargin(p, 0.2)` → `ContainsEdgeAware(p, …, EdgeMargins.For(Edges, ledge 0, flat 0.2))`. Ledge 변 바깥 0~0.2 띠에 떨어진 돌은 **이제 낙**이다.
- 플레이 중: Ledge 선을 `LedgeScreenEpsilon`(0.02, 투영 부동소수 오차 흡수용 수치 허용치일 뿐 유예가 아님)보다 넘으면 낙이다. Flat 쪽은 기존 유클리드 0.8 규칙을 그대로 쓴다. Flat 변만 있는 보드라면 판정 결과가 현행과 비트 단위로 같아야 한다(테스트로 잠근다).
  ```
  IsNakScreen(pos):
    if 하늘면제 적용(pos.y > max(backY + 0.8, SkyFloorY)) && Back == Flat: return false    // 현행 유지(Flat 뒷변)
    if 사다리꼴 안: return false
    for each Ledge 변 e: if 바깥쪽 부호거리(pos, e) > ledgeEps: return true             // D9 (D9-b면 Back Ledge 포함)
    return DistanceToQuadBoundary(pos) > 0.8                                           // 현행 Flat 규칙
  ```
- "Ledge를 하나라도 넘으면 Ledge" 규칙과 같은 모양이다. 예를 들어 25살 앞(Ledge)×우(Flat) 모서리에서는, 앞선을 넘었으면 낙(Ledge)이고 우측만 넘었으면 유예 0.8을 적용한다.

- Ledge 변 = 보이는 가장자리, Flat 변 = 유예 0.8 / 뿌리기 0.2
- 낙 연출과 실패까지의 시간

  - 좌·우·뒤 변은 h<0이 되는 즉시 판 그림 뒤로 들어가므로 판 위에 남지 않는다.

**WatchPhysicsFall (M2, 튕김)** — 돌을 움직이지 않는다. 물리 그대로 둔다. 하는 일은 셋뿐이다: 그림자 차단, "화면 밖이거나 0.8초 경과"를 감시, 종료 시 렌더러 끔. 받기는 OnStoneFell에서 이미 StopCatch로 끝났으므로 재포착도 없다(HandController.cs:945).

**RestoreAll 복구 목록 (검수 🟡)** — 이 컴포넌트가 바꾼 돌마다 다음을 되돌린다.
- 렌더러 켬
- transform z = 0
- `SetShadowGroundCut(false)`, `SetFlightShadow(false)`
- `EnterScriptedFall`이 저장한 isKinematic·useGravity·collider.enabled 복원

그 직후 ResetAllStones가 `SetState(OnBoard)`로 상태에 맞는 값을 다시 쓴다.
검증 항목: 실패·리셋 후 전 돌의 렌더러 켜짐, OnBoard 콜라이더 켜짐, z=0을 로그로 확인한다.

**그림자 규칙**

- 낙 돌은 **Ledge 선(D9 기준 마진 0)**을 넘는 순간 0.08초에 걸쳐 그림자가 0이 된다. 다시 켜지지 않는다.
- Flat 너머 돌은 그림자를 유지한다(같은 원근 식으로 그 면에 깔린다).
- 튕김 돌(물리, HasBoardMotion=false)은 화면상 그림자보다 아래로 내려가면 그림자를 숨긴다. 현재는 이 경우 가장 진하게 찍힌다(StoneShadow.cs:159-166, 높이가 음수면 normalizedH가 0).

### 5-6. 소리

**착지음 상수 세트 하나 (T3)**
```
NoteSet A (펜타토닉):  semis [0,2,4,7,9],  basePitch 0.80, cueSemi 12   → 0.80~1.35
NoteSet B (좁은 폭):   semis [0,1,2,3,4],  basePitch 0.92, cueSemi 5    → 0.92~1.16 (범위 4반음)
ActiveNoteSet = B, FinishCueEnabled = false, LandClip = "scatter_hit_2"
noteIndex = (안착돌수 ≤ 5) ? 순서 : floor(순서 × 5 / 안착돌수)     // n=10 → 0,0,1,1,2,2,3,3,4,4
pitch = basePitch · 2^(semis[noteIndex]/12)
```
- B를 기본으로 둔 이유: 클릭 샘플을 1.3 넘게 올리면 얇아지고, 상승 5음은 멜로디로 들려 장난감 톤이 된다(검수 🟡). B는 "올라간다"만 남기고 멜로디는 없다.
- 순서는 첫 접촉 시각(출발지연 + T_i) 기준으로 미리 정렬한다. 낙 돌은 순서에서 빠진다.
- 둘째 접촉: 같은 음, 볼륨 0.25. **n ≤ 5일 때만** 낸다(보이스 예산).
- Flat 낙 둔탁음: 같은 클립, 피치 0.62, 볼륨 0.60(둘째 접촉 0.20, n ≤ 5일 때만).
- 장외음 `out_of_bounds`: 낙 대기 1건당 1회. 첫 낙 돌이 끝날 때 낸다(교차 순간에는 소리 없음).
- **보이스 예산 (검수 🔴7):** 착지 전용 보이스 12개, 가장 오래된 것부터 빼앗는다. 최악은 n=10 첫 접촉 10 + Flat 둔탁 ≤ 12이고, 둘째 접촉은 n>5에서 없다. 달그락 전용 2개(게이지 중에만, 착지와 시간이 겹치지 않음). 기존 `PlaySFX`·`sfxSource`는 손대지 않는다.
- 새 오디오 에셋: 필요 없다. 청취 결과 마무리음이 얇으면 클립 1개를 확보하고 상수만 바꾼다.

## 10. GATE 3.5 — 유저 체험 시뮬레이션

**(M1-가) 10살 뿌리기, 돌 하나가 왼쪽 가장자리 너머로 (좌 Ledge)**
```
[반응] 대부분 퐁퐁 착지. 왼쪽으로 간 돌은 책상 왼쪽 모서리 위를 지나는 순간 그림자가 사르르 사라진다.
       포물선을 그대로 이어가다 책상 면 높이 아래로 내려가는 순간 책상 그림 뒤로 들어가 보이지 않는다.
       책상 위를 미끄러져 내려가는 장면은 없다(T4). 사라진 직후 멀리서 "툭"(장외음 1회), 0.3초 뒤 "낙!".
[감정] "옆으로 떨어졌네"가 한눈에 보인다. 허공에서 소리가 나거나 멈칫하는 순간이 없다.
```

**(M1-나) 25살, 오른쪽(Flat)으로 나가다 앞(Ledge) 선까지 넘는 돌**
```
[반응] 오른쪽 패드 바깥 책상 면 위로 날아가는 동안 그림자가 책상 면에 붙어 따라간다.
       앞쪽 가장자리 선을 넘는 순간 그림자가 사라지고 책상 앞으로 뚝 떨어져 화면 밖으로.
[감정] 바닥이 있는 곳에서는 그림자가 있고, 없는 곳에서는 사라진다. 규칙이 일관되게 보인다.
```

**(M2-가) 10살(전 변 Ledge), 줍는 중 돌 하나가 앞쪽으로 밀려 가장자리를 넘음**
```
[화면] 2단. 바닥에 돌 셋, 던진 돌은 공중. 앞쪽 돌 하나가 다른 돌에 밀려 책상 앞모서리로 미끄러진다.
[조작] 꾹 누른 채 줍는 중
[반응] 돌의 중심이 보이는 앞모서리를 넘는 순간(D9) 그림자가 사라지고, 그 자리에서 책상 앞면 앞으로 뚝 떨어진다.
       손은 더 줍지 못한다. 던진 돌은 받기 판정 없이 원래 궤적대로 바닥에 내려와 앉는다. 다른 돌은 그대로다.
       돌이 화면 밖으로 나가는 순간 "툭", 0.3초 뒤 "낙!" → 회귀. 전체 기다림은 약 0.5초.
[감정] "모서리를 넘었으니 떨어졌다"를 눈이 먼저 안다. 허공 위에서 떠 있다 늦게 죽는 일이 없다.
```

**(M2-나) 40살 오른쪽(Flat)**
```
[반응] 돌이 유예 띠(0.8) 끝을 넘는 순간 그 자리에 선다. 그림자는 탁자 면에 남는다. 장외음, 0.3초 뒤 "낙!".
[감정] 탁자 위에 멀쩡히 놓인 돌인데 "선 밖"이라 죽는다. 억울하게 느낄 수 있다 → 사용자 체감 확인 항목.
```
